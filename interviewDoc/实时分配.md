| 类型              | 做什么                                  | 并发单位             |
| ----------------- | --------------------------------------- | -------------------- |
| Top-K 候选 worker | 为订单找最近的 K 位骑手                 | 不同订单或不同 Batch |
| offer worker      | 向选中的骑手发 WebSocket 邀请并等待回复 | 不同订单             |

不是多个 Top-K worker 一起搜索同一笔订单。 一笔订单只交给其中一个候选 worker；这个 worker 为它算出 Top-K 候选名单。假设有订单 A、B、C 和两个候选 worker，可能是 worker 1 处理 A、C，worker 2 处理 B。

有界数量的 offer worker 指等待骑手回复的 goroutine 数量有上限. (比如2个)

> 若同时有第三笔订单 C，它可能需要先在有界队列中等一个 offer worker 空出来。

1. offer worker 1 为订单 A 邀请骑手 107，等待回复；
2. 同时，offer worker 2 为订单 B 邀请骑手 103，等待回复；
3. 107 拒绝 A 后，系统为 A 重选骑手，再安排一次邀请。

对同一笔订单，候选搜索做一次 Top-K；邀请通常逐位进行，拒单后才邀请下一位。并发主要用于让多笔订单同时推进，而不是让多名骑手同时抢同一笔订单。

internal/ ：HTTP 接订单、WebSocket 连骑手 → 复用匹配流水线找候选人 → 发邀请并等回复 → 更新账本

使用 WebSocket 长连接，是为了让系统能主动推送订单：骑手上线时连一次，之后有订单就立即收到邀请；骑手接单或拒单，也沿同一连接回复。如果只用普通 HTTP，通常要让骑手端不断询问“有新订单吗”，既有延迟，也会产生许多无用请求。

- ws/rider/handler.go 管一条websocket连接上的对话：接入、读取骑手消息、心跳和断线。
- realtime/manager.go 管所有骑手的连接表：系统选中骑手 107 时，能找到 107 当前的连接并发送邀请。

这样，即使多笔订单由不同的 offer worker 并发处理，它们也能通过 manager 找到各自的骑手；骑手回复则由 handler 送回对应的派单请求。接单后才提交分配，断线或超时则可以换人。
